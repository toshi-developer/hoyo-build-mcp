## 設計判断とその理由

### スタレだけ Mihomo のままにした

当初は「全部 Enka に寄せる」と提案したが、**変更した**。

Enka は **ID しか返さない**（`avatarId: 10000052` など）。原神・ゼンゼロは変換表
（`store/*.json`）を噛ませて日本語名に解決したが、スタレの Mihomo `sr_info_parsed` は
名前・ステータス・遺物のサブステと強化回数まで整形済みで返す。Enka に寄せると
自前で組み直すことになり**質が下がる**ため、データ元は使い分けた。

統一したのは入口（`build_*` ツールの `game` 引数）だけ。

### 名前を推測で埋めない

原神の聖遺物セット名のうち、Enka の辞書（`loc.json` / `gi/locs.json`）に **ja / en とも
載っていないものが2件**ある。名前を推測して書くと助言を誤らせるため、
`giSetLabel()` で次のように出している。

```
(未収録セットID:15020 / 2セット:元素チャージ効率+20.0%)
```

セット効果は `gi/relics.json` の `Sets[].AddProps` から機械的に導いているので正確。
**4セットか2セットかの判別も正しく効く**（グループ化は名前でなくハッシュで行うため）。

確認済みの未収録: `setId=15020`（2セット: 元素チャージ効率+20%）、
`setId=14003`（2セット: prop50 +0.4）。

### ZZZ の数値スケール

ZZZ のプロパティ値は ×100 で入っている（`HpMax_Ratio: 300` → 3.0%）。
`property.json` の `Format` に `%` が含まれるものを百分率として `/100` している。
**A ランクディスクの実値でしか検証していない**ので、S ランクや高強化での妥当性は未確認。

## 未解決の検討事項

着手するならこの順が効果的だと思う。

### 1. 所持キャラ全件の取得を原神・ゼンゼロにも広げるか（効果大）

現状、**ショーケースに並べたキャラしか読めない**という制約が3タイトル共通で残っている。
実際この制約のせいで「おすすめパーティを出せない」場面が起きた（スタレで、盾役2人しか
ショーケースに入っていなかった）。

スタレには既に `hsr_fetch_roster`（HoYoLAB 戦績 API、要 `HOYOLAB_COOKIE`）が入っていて
所持キャラ全件が取れる。**原神・ゼンゼロにも同じ API がある**ので、同じ仕組みを広げれば
制約が外れる。エンドポイントは `/game_record/genshin/api/character` 系、ゼンゼロは
`/event/game_record_zzz/api/zzz/avatar/...` 系（要確認）。

注意: HoYoLAB の DS 署名ソルトは向こうの更新で定期的に壊れる（`retcode=-10001`）。
`HOYOLAB_DS_SALT` / `HOYOLAB_DS_VARIANT` / `HOYOLAB_APP_VERSION` で差し替えられるように
してあるが、**壊れたことに気づく手段が無い**。

### 2. MCP サーバー名が `hsr-build` のまま（要整理）

登録名・データディレクトリ（`~/.hsr-build-mcp/`）ともスタレ時代の名前が残っている。
リポジトリ名は `game-build-mcp` にしたので、次のどちらかに揃えたい。

- 登録名を `game-build` にし、`HSR_DATA_DIR` で `~/.game-build-mcp` を指す
  → **既存のスナップショット履歴を引き継ぐ移動が要る**
- 名前は据え置き、README にだけ由来を書く（今はこちら）

### 3. テストが無い

変換表の構造が変わると静かに `(ID:xxxxx)` だらけになる。最低限、
**保存済みスナップショットを入力にした整形のスナップショットテスト**があると
Enka 側の仕様変更に気づける。

### 4. 変換表キャッシュ7日の妥当性

新キャラ実装直後は7日待つと `(ID:...)` になる。`ttl` のように
サーバー側の指示に従う仕組みは無いので、手動更新の手段（`force` 引数）があってもよい。

### 5. 原神の天賦レベル表示

`meta.SkillOrder` の並び順で「通常攻撃 / 元素スキル / 元素爆発」に対応づけているが、
**旅人など複数の元素を持つキャラで正しいか未確認**。命ノ星座による +3 は
`proudSkillExtraLevelMap` から拾っているが、こちらも検証は1キャラ（ベネット C6）だけ。

### 6. エラー時の挙動

Enka が 424（ゲームメンテ中）を返すケースは**実際には踏んでいない**。
メッセージは用意したが、文言が実態と合うかは未確認。
